# Redis 키 설계 (펩시미만잡)

| 키 이름 | 자료구조 | TTL | 무효화 시점 | 용도 |
|---|---|---|---|---|
| `book:ranking` | Sorted Set | 없음(누적) | 거래 요청(가격 제시·교환 제시) 발생 시 점수 +1 | 인기 도서 랭킹 TOP 10 |
| `book:{bookId}:lock` | String(`SET NX EX`) | 수 초(락 보유 시간) | 수락 처리 완료 또는 TTL 만료 시 해제 | 한 책에 여러 교환요청이 동시에 수락되는 것 방지 |

> `book:ranking`엔 거래 요청 수만 그대로 누적(요청 1건당 +1). 조회수는 새로고침으로 쉽게 부풀릴 수 있어 이 점수엔 안 섞고, 랭킹 API(11번)가 응답 시점에 `RankingScoreCalculator`로 `요청수 × 5 + log(조회수+1) × 1`를 계산해 순서만 다시 매김 — 요청이 한 번도 없던 책은 애초에 이 Sorted Set에 없어서 랭킹 대상에서 자동으로 빠짐. 조회수 자체는 `book.view_count` 컬럼(도서 상세 조회 시 +1)에 있음, Redis엔 없음.
>
> 락: 요청 수락 처리 시작 시 `SET book:{bookId}:lock <requestId> NX EX 5` 시도 → 실패하면 이미 다른 요청이 처리 중이므로 "이미 처리됨" 응답. 성공하면 해당 책 상태를 거래완료로 바꾸고 나머지 요청은 자동 거절, 처리 끝나면 락 삭제(또는 TTL로 자연 만료).
