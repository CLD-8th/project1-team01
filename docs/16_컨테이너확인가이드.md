# 컨테이너화 재현 확인 가이드 (펩시미만잡)

> 목적: 각자 컴퓨터(내일은 우분투 VM)에서 지금 main에 있는 소스로 앱 전체가 컨테이너에서 정상 동작하는지 확인.
> 이미지 파일을 주고받는 게 아니라, **각자 같은 소스에서 다시 빌드**해서 똑같은 결과가 나오는지 확인하는 방식임(재현성 확인이 핵심).

## 1. 최신 코드 받기

```bash
git checkout main
git pull origin main
```

## 2. `.env` 파일 준비 (최초 1회)

`.env`는 `.gitignore`에 걸려있어서 git엔 없음. `.env.example`을 그대로 복사해서 씀(팀 공용 로컬 개발값 — 실제 운영 비밀번호 아님).

```bash
cp .env.example .env
```

## 3. 전체 빌드·기동

지금까지는 `docker compose up -d db cache`로 DB·캐시만 띄우고 앱은 IDE에서 직접 돌렸음(빠른 개발용). 이번엔 **app까지 포함해서 이미지 자체를 새로 빌드**함:

```bash
docker compose up -d --build
```

처음엔 Gradle 의존성 받고 빌드하느라 1~2분 걸림. 완료되면 컨테이너 3개(`db`, `cache`, `app`)가 뜸.

## 4. 확인 체크리스트

**① 컨테이너 상태**

```bash
docker compose ps
```

`db`, `cache`가 `(healthy)`, `app`이 `Up` 상태여야 함. `db`/`cache`가 `(health: starting)`이면 몇 초 더 기다렸다 다시 확인.

**② 헬스체크**

```bash
curl http://localhost:8090/actuator/health
```

```json
{"status":"UP"}
```

**③ 화면 접속**

브라우저로 `http://localhost:8090/index.html` 열어서 도서 목록 화면이 뜨는지 확인(빈 목록이어도 정상 — 이 컨테이너는 처음 띄운 거라 데이터가 없음).

**④ (선택) 회원가입→로그인까지 한 번 해보기**

화면에서 가입 → 로그인까지 실제로 눌러보면 DB·JWT까지 전부 살아있는 것까지 확인됨.

## 5. 안 될 때

- **포트 충돌(`port is already allocated`)**: 이전에 IDE로 띄워둔 `./gradlew bootRun`이나 다른 컨테이너가 8090/3307/6380을 이미 쓰고 있을 수 있음 → `docker compose down` 먼저, 그리고 `lsof -iTCP:8090 -sTCP:LISTEN`(맥/리눅스)으로 확인 후 정리
- **`.env` 관련 에러(`Access denied`, 빈 값 등)**: 2번 단계(`.env` 복사)를 빼먹은 경우가 대부분
- 그 외 증상은 `09_트러블슈팅.md`에 비슷한 사례가 있는지 먼저 확인

## 6. 정리(재현 확인 끝난 뒤)

계속 개발할 거면 다시 빠른 루프로 돌아가면 됨:

```bash
docker compose down
docker compose up -d db cache   # app은 IDE에서 직접 실행
```
