# 스켈레톤 재활용 가이드 (펩시미만잡)

> `study-app-skeleton`에서 뭘 그대로 쓰고, 뭘 이름만 바꿔 베끼고, 뭘 새로 짜야 하는지 정리. **Service·Controller는 전부 `TODO` 빈 껍데기**라 "리팩터"가 아니라 참고하며 새로 작성하는 쪽에 가까움.

## 그대로 재사용 (건드리지 않음)

| 패키지/파일 | 내용 |
|---|---|
| `member/*` | 회원가입·조회 — 구현 완료됨 |
| `auth/*` | JWT 로그인·재발급 — 구현 완료됨 |
| `common/BusinessException`, `ErrorResponse`, `GlobalExceptionHandler`, `PageResponse`, `SecurityErrorWriter` | 도메인 무관, 그대로 사용 |
| `static/login.html`, `static/signup.html` | 인증 화면. 교안이 화면 최소화를 허용하니 그대로 써도 충분 |

**주의**: 인증 관련 코드는 아무도 새로 만들지 않기(교안 원칙, 팀 확정 사항).

## 손봐야 하는 것

| 패키지/파일 | 내용 |
|---|---|
| `common/ErrorCode` | 스터디 전용 에러(`STUDY_CLOSED`, `CAPACITY_EXCEEDED` 등) 대신 우리 도메인 에러코드로 교체 |
| `common/SecurityConfig` | `/api/studies` 등 권한 규칙을 우리 `/api/books`, `/api/requests` 기준으로 교체 |

## 구조·패턴만 베껴서 이름·필드 바꾸기

### `StudyPost` → `Book`

| StudyPost | Book | 비고 |
|---|---|---|
| `writer` (Member) | `owner` (Member) | 그대로 |
| `status` (RECRUITING/CLOSED) | `status` (거래중/거래완료) | enum 값만 교체 |
| `title`, `content` | `title`, (설명은 `상태 설명`으로) | |
| `capacity`, `deadline`, `meetingType`, `location`, `startDate` | — | 스터디 전용, 버림 |
| — | `author`, `coverImageUrl`, `accepts_price/swap/giveaway` | 새로 추가 |
| `isWrittenBy()`, `close()` | 동일 패턴 재사용 | 메서드 이름만 맞춰도 됨 |

### `Application` → `ExchangeRequest`

거의 그대로 맞아떨어짐.

| Application | ExchangeRequest | 비고 |
|---|---|---|
| `studyPost` | `book` | 그대로 |
| `applicant` | `requester` | 그대로 |
| `message` | `message` | **필드명까지 그대로 재사용 가능** |
| `status` (PENDING/ACCEPTED/REJECTED) | `status` (요청/거절/수락) | enum 값만 교체, CANCELED는 안 씀 |
| `accept()`, `reject()`, `isPending()`, `isAppliedBy()` | 동일 패턴 재사용 | |
| — | `offeredPrice`(기본 0), `offeredPhotoUrl` | 새로 추가 |

### Repository 패턴

- `findWithWriterById` / `findWithStudyPostById` 같은 `@EntityGraph` fetch-join 패턴 → `findWithOwnerById` / `findWithBookById` 식으로 이름만 바꿔 재사용
- `countByStudyPostIdAndStatus`, `countAcceptedByStudyPostIds`(묶음 집계 `@Query`) → 그대로 스타일 재사용

## 전부 새로 작성

- **Controller 11개** — `StudyController`/`ApplicationController`에 `@GetMapping` 등 매핑이 아예 없음(주석만 있음). API 목록(`03_API목록.md`) 기준으로 처음부터 작성
- **Service 로직 전부** — 현재 `throw new UnsupportedOperationException("TODO N")` 상태. 주석에 판단 순서 힌트가 있으니 참고만
- **DTO** — 필드가 다르므로 이름만 참고하고 새로 작성

## 삭제 대상

- `review/*` 패키지 전체 (후기 기능 — 헌책방엔 없음)
- `static/study.html`, `static/mypage.html`, `static/form.html`, `static/index.html`, `static/parts.html`, `static/js/study-*.js` — 스터디 모집 화면. Figma로 새로 설계했으니 불필요
- `db/schema.sql`, `db/sample.sql` — `study_app` 스키마 기준. 계정 생성 방식(`CREATE USER ... GRANT`)만 참고하고 우리 스키마로 새로 작성

## 화면 구현 기준

Figma 와이어프레임(`헌책방 와이어프레임`)대로 만들면 제일 좋지만, 시간 부족하면 **최대한 비슷하게만** 만들어도 됨 — 픽셀 단위로 맞출 필요 없음. 평가·게이트 기준은 화면 완성도가 아니라 기능 동작 여부.
