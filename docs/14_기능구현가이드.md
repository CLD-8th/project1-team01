# 기능 구현 가이드 (펩시미만잡)

> 브랜치별로 어떤 컨트롤러를 만들고, 어떤 DB(엔티티·리포지토리)를 쓰고, 뭘 구현해야 하는지 상세 정리. 인증된 사용자 식별자는 어디서든 `@AuthenticationPrincipal Long memberId`로 받으면 됨(토큰 필터가 principal에 회원 id를 직접 담아둠).

---

## `feature/1-도서목록상세` — 홍정민

**컨트롤러**: `com.example.study.book.BookController` (신규) — `@RestController @RequestMapping("/api/books")`

**DB**: `BookRepository`
- 1번(목록): `search(keyword, status, pageable)` — 이미 있음
- 2번(상세): `findWithOwnerById(id)` — 이미 있음

**구현**
1. `GET /api/books?page=&size=&keyword=&status=`
   - `PageRequest.of(page, size, Sort.by(Sort.Direction.DESC, "id"))`
   - `status` 문자열이 오면 `BookStatus.valueOf(status)`로 변환(대소문자·오타는 `INVALID_INPUT`)
   - 결과를 `PageResponse.of(page, mapper)`(공통 클래스, 이미 있음)로 감싸서 반환
   - 인증 불필요
2. `GET /api/books/{bookId}`
   - `findWithOwnerById` 없으면 `BusinessException(ErrorCode.NOT_FOUND)`
   - 인증 불필요

## `feature/3-도서등록` — 홍정민

**컨트롤러**: 같은 `BookController`에 `POST` 매핑 추가

**DB**: `new Book(title, author, coverImageUrl, description, owner, acceptsPrice, acceptsSwap, acceptsGiveaway)` 생성자 이미 있음 → `bookRepository.save()`

**구현**
1. `POST /api/books`, `@AuthenticationPrincipal Long memberId`로 등록자 확인 → `memberService`로 `Member` 조회(제공된 메서드 확인)
2. body: `title`, `author`, `coverImageUrl`(10번 업로드 결과 URL), `description`, `acceptsPrice`/`acceptsSwap`/`acceptsGiveaway`
3. 저장 후 `201 Created` + `Location` 헤더(`ResponseEntity.created(URI.create(...))`)
4. `coverImageUrl`은 10번(사진업로드)이 먼저 끝나야 실제 값이 생기지만, 개발 중엔 아무 문자열이나 넣고 테스트해도 됨(병렬 진행 가능)

## `feature/10-사진업로드` — 홍정민

**컨트롤러**: `BookController`에 추가하거나 별도 `BookImageController`

**DB 아님** — 파일 저장(로컬 볼륨, `compose.yaml`에 이미 `uploads` 볼륨 마운트돼 있음)

**구현**
1. `POST /api/books/images` (multipart)
2. `application.yml`/`application-prod.yml`에 `app.upload-dir` 설정 추가 필요(교안 예시 참고 — 없으면 새로 추가)
3. 저장 후 `{"url": "/uploads/xxxx.jpg"}` 형태로 반환 → 이 값을 3번(등록)·4번(거래요청)에서 그대로 씀
4. 실제 S3는 시간 없으면 생략, 설계 문서에만 반영(교안 원칙)

## `feature/4-거래요청` — 문병현

**컨트롤러**: 신규 패키지 `com.example.study.request`의 `ExchangeRequestController` — `@RequestMapping("/api/books/{bookId}/requests")` (POST만)

**DB**: `BookRepository.findWithOwnerById(bookId)`(대상 확인) → `new ExchangeRequest(book, requester, offeredPrice, offeredPhotoUrl, message)` → `exchangeRequestRepository.save()`

**Redis**: 저장 성공 시 `book:ranking`에 `ZINCRBY 1 <bookId>` (`StringRedisTemplate.opsForZSet().incrementScore(...)`) — `04_Redis키설계.md` 참고

**구현(판단 순서)**
1. 대상 책 확인 → 없으면 404
2. 본인 책이면 거부 → `ErrorCode.SELF_REQUEST`
3. 책 상태가 `TRADING`이 아니면 거부 → `ErrorCode.BOOK_NOT_TRADING`
4. `offeredPrice`(기본 0, 음수 불가) + `offeredPhotoUrl`(선택) + `message`(선택)로 저장
5. 랭킹 점수 +1

## `feature/8-요청수락거절` — 문병현

**컨트롤러**: 같은 `ExchangeRequestController`에 `POST /api/requests/{requestId}/accept`, `POST /api/requests/{requestId}/reject` 추가

**DB**: `ExchangeRequestRepository.findWithBookById(requestId)`, `findByBookIdAndStatus(bookId, PENDING)`(나머지 요청 조회용)

**Redis**: 수락 시 `SET book:{bookId}:lock <requestId> NX EX 5` 락 시도(`04_Redis키설계.md` 참고)

**구현(수락)**
1. 요청 조회 → 없으면 404
2. 요청 대상 책의 등록자가 본인인지 확인 → 아니면 403 `FORBIDDEN`
3. 요청이 `PENDING`인지 확인 → 아니면 400 `ALREADY_PROCESSED`
4. 락 획득 시도 → 실패하면 409 `LOCK_CONFLICT`(이미 다른 요청이 처리 중)
5. `ExchangeRequest.accept()`, `Book.complete()`
6. `findByBookIdAndStatus(bookId, PENDING)`으로 남은 대기 요청 전부 조회해서 각각 `reject()`
7. 락은 처리 끝나면 지우거나 TTL(5초)로 자연 해제되게 둬도 됨

**구현(거절)**
1. 요청 조회 → 없으면 404
2. 등록자 본인 확인 → 아니면 403
3. `PENDING` 확인 → 아니면 400 `ALREADY_PROCESSED`
4. `ExchangeRequest.reject()` — 락 필요 없음(정원 개념이 없어서 경쟁 상황이 아님)

## `feature/11-인기랭킹` — 전동환

**컨트롤러**: `BookController`에 추가하거나 별도 `RankingController` — `GET /api/books/ranking`

**Redis**: `ZREVRANGE book:ranking 0 9` (`StringRedisTemplate.opsForZSet().reverseRange(...)`)

**DB**: 뽑힌 bookId 목록으로 `BookRepository.findAllById(ids)` — Redis가 준 순서 그대로 정렬해서 반환(JPA는 순서 보장 안 하니 직접 재정렬 필요)

**구현**: 인증 불필요, 랭킹에 없으면 빈 리스트

## 공통 참고

- 에러는 전부 `throw new BusinessException(ErrorCode.XXX, "설명")` — `GlobalExceptionHandler`가 알아서 응답 변환(이미 있음)
- 새 에러 사유 필요하면 `common/ErrorCode`에 추가해서 씀
- 페이지 응답은 `PageResponse.of(page, mapper)` 재사용
- DTO는 각자 패키지 밑에 `dto/` 서브패키지로
