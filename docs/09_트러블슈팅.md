# 트러블슈팅 (펩시미만잡)

> 증상 → 원인 → 해결 순서로 기록. 겪은 사람이 그때그때 추가.

### [2026-09-29] `gh auth login` 도중 `mkdir ~/.config/gh: permission denied`

- 증상: GitHub CLI 로그인 시작하자마자 권한 오류로 실패
- 원인: `~/.config` 폴더가 예전에 다른 프로그램이 관리자 권한(`sudo`)으로 만들어놔서 현재 계정 소유가 아님
- 해결: `sudo chown -R $(whoami) ~/.config` 실행 후 재시도. 그래도 안 되면 `export GH_CONFIG_DIR="$HOME/.gh-config"`로 설정 위치 자체를 바꿔서 우회

### [2026-09-29] Windows에서 `docker`/`gh` 명령어가 "인식할 수 없음" 뜸(설치는 했는데)

- 증상: winget으로 분명히 설치했는데 PowerShell에서 `docker --version`, `gh --version`이 명령어를 못 찾음
- 원인: 설치 전부터 열려있던 PowerShell 창은 PATH 환경변수가 갱신 안 된 상태로 유지됨
- 해결: PowerShell 창을 완전히 닫고 새로 열기. 그래도 안 되면 컴퓨터 재부팅(WSL2 최초 설치 시 자주 필요)

### [2026-09-29] Windows에서 `docker exec -it app-db-1 ...` 500 Internal Server Error

- 증상: `docker compose ps`는 정상인데 `docker exec`만 `dockerDesktopLinuxEngine` 관련 500 에러
- 원인: Docker Desktop을 막 설치·재시작한 직후라 엔진이 완전히 안정화되지 않은 상태로 추정(일시적)
- 해결: 같은 명령 재시도로 해결됨. 안 되면 `-it` 빼고 시도하거나 `docker compose restart db`

### [2026-09-29] `application.yml` 자격증명이 `.env`랑 안 맞아서 IDE 직접 실행 시 DB 연결 실패

- 증상: `docker compose up -d --build`(전체)는 되는데 `docker compose up -d db cache` + IDE 직접 실행 조합은 `Access denied`
- 원인: `application.yml`이 스켈레톤 기본값(`study_app`/`study`/`Study!1234`)을 그대로 쓰고 있어서 `.env`의 실제 DB 계정과 불일치. Redis 설정도 아예 없었음
- 해결: `application.yml`을 `.env.example`과 동일한 값(`hunchaekbang`/`hunchaekbang1234`)으로 맞추고 Redis 설정 추가(PR #23)

### [2026-09-29] `compose.yaml`의 db/cache에 호스트 포트 매핑이 없어서 IDE 직접 실행 시 접속 불가

- 증상: 컨테이너는 healthy인데 `localhost:3306`으로 연결이 안 됨(엉뚱한 로컬 MySQL로 연결되거나 아예 실패)
- 원인: 교안 예시 compose.yaml은 db/cache를 컨테이너 내부망(`db:3306`)으로만 쓰는 걸 가정 — 호스트에서 직접 붙는 경우를 안 다룸. 로컬에 이미 다른 MySQL이 3306번을 쓰고 있었던 것도 원인
- 해결: db는 `3307:3306`, cache는 `6380:6379`로 호스트 포트 매핑 추가(PR #23), `application.yml`도 이 포트로 맞춤
