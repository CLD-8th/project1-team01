# 단계별 진화 설계 (펩시미만잡)

다이어그램은 1단계 → 2단계 → 3단계로 제출. 각 단계의 한계가 다음 단계로 넘어가는 근거가 되어야 함.

## 1단계 기준선

- 구성: compose를 EC2 1대로 이전 (app·db·cache 전부 한 인스턴스)
- 남는 한계: 단일 장애점, DB 공개, 수동 운영

## 2단계 관리형 전환

- 구성: DB·캐시·파일을 관리형으로 분리, DB를 프라이빗 서브넷으로 격리
- 남는 한계: 단일 AZ, EC2 1대, 부하 분산 없음

## 3단계 고가용성

- 구성: 2개 AZ, ALB, Auto Scaling, Multi-AZ RDS, ElastiCache Primary/Replica
- 비용 증가 → 비용 산정으로 정당화

(다이어그램은 draw.io로 별도 작성 후 이미지 첨부)
