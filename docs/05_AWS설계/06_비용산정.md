# 비용 산정 (펩시미만잡)

AWS Pricing Calculator, 리전 아시아 태평양(서울, ap-northeast-2).

산정 대상: EC2, ALB, RDS(Multi-AZ), NAT Gateway, 데이터 전송. (ElastiCache·S3는 소액이라 추후 추가)

## 공통 조건

| 항목 | 값 |
|---|---|
| 리전 | Asia Pacific (Seoul) |
| EC2 유형 | t4g.small |
| RDS 유형 | db.t4g.small |
| 데이터 전송 | 월 10GB |

## 입력 절차

**STEP 1. 리전 선택**: Asia Pacific (Seoul)

**STEP 2. EC2**

| 입력 항목 | 값 |
|---|---|
| 서비스 | Amazon EC2 |
| OS | Linux |
| Instance type | t4g.small |
| Number of instances | 2 |
| Utilization | 100% Utilized/Month |
| EBS Storage | 30 GB |

**STEP 3. ALB**

| 입력 항목 | 값 |
|---|---|
| 서비스 | Elastic Load Balancing (Application Load Balancer) |
| Number of ALBs | 1 |
| ALB당 평균 새 연결 수 | 3 |
| 평균 연결 지속 시간 | 3 |
| ALB당 초당 평균 요청 수 | 3 |

**STEP 4. RDS**

| 입력 항목 | 값 |
|---|---|
| 서비스 | Amazon RDS for MySQL |
| Instance type | db.t4g.small |
| Deployment option | **Multi-AZ** (ADR-02) |
| Storage | 100 GB |

**STEP 5. NAT Gateway**

| 입력 항목 | 값 |
|---|---|
| 리전 NAT 게이트웨이 수 | 1 |
| 리전 NAT 게이트웨이가 활성화된 가용 영역 수 | 1 |
| 리전 NAT 게이트웨이별로 처리된 데이터 | 100 GB/월 |

> Pricing Calculator의 "NAT 게이트웨이 수"(Zonal) 필드는 0까지 내려가지만, "리전 NAT 게이트웨이" 필드는 최소 1이 강제되어 0으로 둘 수 없음 — 부득이하게 Zonal은 0, Regional(AZ 1개)로 입력함. 금액은 Zonal 1개와 동일(AZ당 과금 방식이 같음). 실제 설계는 ADR-03대로 **Zonal NAT Gateway 1개**.

**STEP 6. 데이터 전송** (NAT Gateway 요금엔 아웃바운드 전송 요금 미포함, 별도 추가)

| 입력 항목 | 값 |
|---|---|
| Outbound Data Transfer to Internet | 100 GB/월 |
| Inbound | 0 |

## 비용 최적화 결정 요약

| 결정 | 절감 효과(추정) | 근거 |
|---|---|---|
| NAT Gateway 2개→1개 | 월 약 $33 절감 | 사용자 트래픽 경로엔 영향 없음(ADR-03) |
| ElastiCache Replica 미적용 | 월 약 $12 절감 | 랭킹은 DB에서 재생성 가능한 비영속 데이터(ADR-04) |
| RDS Multi-AZ | 유지(절감 안 함, 비용의 59% 차지) | RTO 30분 요구사항과 직결, 영속 데이터라 이중화 필요(ADR-02) |

**비용 절반으로 줄여야 한다면**: RDS를 Single-AZ로 전환(월 $127→약 $64)해 가장 큰 항목을 줄임. 위험은 `09_필수질문답변.md` 참고(RTO가 30분을 넘어 수 시간 단위로 늘어날 수 있음).
