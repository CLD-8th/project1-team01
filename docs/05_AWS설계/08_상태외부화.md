# 상태 외부화: 수평 확장의 조건 (펩시미만잡)

발표에서 반드시 답해야 하는 질문: "우리 앱에서 상태(state)는 어디에 있고, AWS에서는 어디로 옮겼는가?"

| 상태 | 로컬(compose) | AWS |
|---|---|---|
| 세션·랭킹 | Redis 컨테이너 | ElastiCache |
| 영속 데이터 | MySQL 컨테이너 | RDS Multi-AZ |
| 업로드 파일 | uploads 볼륨 | S3 |
| 애플리케이션 서버 | app 컨테이너 | 상태 없음(무상태) → EC2 Auto Scaling으로 수평 확장 |

세션·랭킹·업로드 파일을 전부 외부(ElastiCache/S3)로 뺐기 때문에 앱 서버 자체엔 상태가 남지 않고, 그래서 EC2를 몇 대로 늘려도(Auto Scaling) 어느 인스턴스가 요청을 받든 같은 결과가 나온다.
