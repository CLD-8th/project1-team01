# 용량 산정 (펩시미만잡)

가정은 아래 네 개만 세우고 나머지는 전부 계산으로 끌어냄 — 질문받을 지점을 네 개로 줄이는 게 목적.

```
DAU ──(피크 집중률)──▶ 피크 시간대 방문자
                            │
                     (평균 체류 시간 ÷ 피크 시간대 길이, Little's Law)
                            ▼
                     피크 동시접속자 ──(Think Time)──▶ 피크 RPS ──(급증 배수)──▶ 급증 RPS
```

## 팀이 확정한 네 가지 가정 (09-30 회의, 최종)

| 가정 | 값 | 근거 |
|---|---|---|
| 피크 집중률 | 12% | 거래가 퇴근시간 후 집중되는 점을 고려한 수치 |
| 평균 체류 시간 | 12분 | 거래 목록을 확인 후 거래 요청 및 거래도서 등록시간까지 고려 |
| Think Time | 12초 | 사용자가 책표지나 제목을 보고 책 상세에 들어가는 시간 |
| 급증 배수 | 3배 | 개강 직전 수요 증가와 인기 도서 링크 공유로 요청이 순간적으로 몰리는 상황을 가정 |

DAU 2,400 · 피크 시간대 19:00~21:00(2시간 = 120분).

## 계산 (피크·급증)

| 단계 | 계산 | 값 |
|---|---|---|
| 피크 시간대 방문자 | DAU 2,400 × 피크집중률 12% | 288명 |
| 피크 동시접속자 (Little's Law) | 288 × (평균체류시간 12분 ÷ 피크시간대 120분) | 29명 |
| 피크 RPS | 29 ÷ Think Time 12초 | 2.4 RPS |
| 급증 RPS | 2.4 × 급증배수 3배 | **7.2 RPS** |

## 계산 (평상시, 참고용)

동시 접속 비율은 "매일 켜는 서비스가 아니라 필요할 때만 켜는 서비스"라는 점을 고려해 0.83%로 별도 가정. 최종 대수 산정에는 쓰이지 않고 참고용(평상시 부하가 피크 대비 얼마나 작은지 보여주는 용도).

| 단계 | 계산 | 값 |
|---|---|---|
| 평상시 동접자 | DAU 2,400 × 동시접속비율 0.83% | 20명 |
| 평상시 RPS | 20 ÷ Think Time 12초 | 1.67 RPS |

## 인스턴스 대수 · Auto Scaling

| 항목 | 값 | 근거 |
|---|---|---|
| 인스턴스 1대 처리량 | 20 RPS (가정) | 실제 값은 부하 테스트(k6)로 측정해야 함. 09-22 교안 벤치마크(461~632 RPS, 더 좋은 스펙 기준)보다 훨씬 보수적으로 낮춰 잡음 |
| 최소 용량 | 2 | AZ 이중화 조건(AZ당 1대) — 급증 RPS 7.2는 1대로도 충분하지만 가용성 목표 99.9% 때문에 상시 2대 유지 |
| 희망 용량 | 2 | 최소와 동일 |
| 최대 용량 | 3 | 최소×급증배수(2×3=6)가 원 공식이지만 비용 부담 고려해 3으로 조정 — 급증 7.2RPS는 2대(40RPS)로도 충분, 3번째는 처리량 가정 오차·AZ 장애와 급증 동시 발생 대비 여유 |
| 목표 지표 | 평균 CPU 60% | 급증 7.2RPS÷2대=대당 3.6RPS→CPU 약 18%. AZ 장애 시 남은 1대가 전체 수용해도 CPU 약 36%로 60% 밑돎(과부하 없음). 실제 트래픽이 가정보다 커져 60% 넘으면 Auto Scaling이 최대 3대까지 확장 |
| 인스턴스 워밍업 | 300초 | Spring Boot 기동 후 애플리케이션 준비까지 소요 시간 가정 |
| 헬스 체크 | ELB, 유예 300초 | 프로세스 생존이 아니라 `/actuator/health` 응답으로 판정. 기동 중 인스턴스가 비정상으로 오판되어 교체되는 것을 방지 |
| 스케일링 정책 | 대상 추적(기본) + **예약 조정 병행** | 도메인정의서의 급증 이벤트(시험 시즌·학기 초 모집)는 시점이 예측 가능 — 09-22 교안이 "피크 시각이 확정적인데 지표 반응을 기다릴 이유가 없다"고 짚은 사례. 해당 시즌 직전에 예약 조정으로 희망 용량을 3으로 미리 올려두고, 그 위에 대상 추적(CPU 60%)을 병행 |

> **실무팁** — "방문자 수"를 바로 "동시접속자"로 쓰면 안 됨(체류시간 반영 전). Little's Law(동시접속자 = 도착률 × 체류시간)로 한 단계 거쳐야 실제 동시 사용자 수가 나옴.

- **p95 기준 SLO**: 도서 목록 조회 p95 500ms 이하로 설정(평균 대신 백분위 사용).
- **병목 위치**: 아직 실측 전. Redis는 랭킹·락 용도로만 쓰여 조회 캐시가 없으므로, DB가 캐시보다 먼저 한계에 부딪힐 가능성을 우선 의심(트래픽 늘면 조회 캐시 도입 또는 읽기 전용 복제본 검토).
